# LLM Jailbreak Evaluation Harness - Agent Instructions

This document contains project-level instructions for OpenCode agents working on this repository.

## Core Constraints

### Local Inference Only
- **Never** send evaluation cases to cloud models (OpenAI, Anthropic, Google, OpenRouter, etc.)
- **Only** use local Ollama endpoints (127.0.0.1, localhost, ::1)
- The harness is designed for controlled AI-model research on locally hosted models

### Model Output Safety
- **Never** execute content generated by evaluated models
- **Never** automatically run shell commands suggested by evaluated models
- **Never** treat generated model output as trusted code
- Store all model output as inert experimental data only

### Experiment Integrity
- Preserve raw experiment data immutably in `results/<experiment-id>/raw.jsonl`
- Never modify raw results after creation
- Classifier corrections go in separate scored files
- Audit before modifying experiment state

### Ollama Management
- **Never** delete Ollama models (`ollama rm`)
- **Never** modify user's existing Ollama model definitions
- The harness may query Ollama state but must not mutate model installation state
- Kill only harness processes, never unrelated Ollama processes

### Reproducibility
- Keep experiments reproducible with full parameter recording
- Each trial records: model, digest, seed, temperature, top_p, top_k, condition, case, reasoning mode
- Use deterministic trial IDs for resume capability
- Lock files prevent concurrent runs on same experiment directory

## Development Workflow

### Before Committing
1. Run all tests: `pytest tests/ -v`
2. Run smoke experiment with small model
3. Verify raw result counts match expectations
4. Check that `git status` is clean

### Code Style
- Use type hints throughout
- Use dataclasses for structured data
- Use pathlib for file operations
- Use deterministic serialization (JSON with sorted keys)
- Use UTF-8 explicitly
- Atomic writes for summary files

### Adding New Features
1. Add test cases first (classifier patterns, analysis functions)
2. Implement minimal functionality
3. Update documentation
4. Run full test suite

## Key Commands

```bash
# Run preflight checks
python -m src.runner --config config.yaml --preflight

# Dry run (show plan without executing)
python -m src.runner --config config.yaml --dry-run

# Run experiment
python -m src.runner --config config.yaml

# Resume interrupted experiment
python -m src.runner --config config.yaml --resume results/<experiment-id>

# Run tests
pytest tests/ -v
```

## Classifier Rules

The classifier in `src/classify.py` uses deterministic regex patterns. When modifying:
1. Add test cases in `test_classifier.py` for new patterns
2. Document matched_rules for auditability
3. Never use LLM-based classification by default
4. Raw results always remain authoritative

## Experimental Design Principles

1. **Change ONE variable at a time** - Hold all other parameters constant
2. **Multiple repetitions** - Default 10 trials/condition (dev), 25+ for publication
3. **Controlled conditions** - Baseline, neutral, style_only, explicit_anti_refusal, persona, etc.
4. **Distinguish behaviors** - Hard refusal, soft refusal, warning, lecture, redirect, hedging, direct answer
5. **No overclaiming** - Report "observed difference", not "proved improvement"

## Research Hypotheses (for reference, not encoded in code)

1. Explicit anti-refusal language may increase alignment behavior (adversarial training association)
2. Abliterated models may reduce explicit refusal but retain safety conversational patterns

These are tested by the experimental design, not assumed in the classifier.
